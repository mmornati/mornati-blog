Reading it

  • Same model family: the versions agree on the topic for 95–96% of prompts and on the routed model for 84–86%.
  • 1.14 is the better classifier (risk, calibration, a bit faster) but is confident less often, so the router plays safe more often.
  • A lower threshold doesn't close the gap: 1.14 costs more at 0.7 and 0.6 too.
  • Only 11–13 prompts per run route differently: a direction, not a measurement.
  • Side finding: both versions score risk ~0.53 above the labels. A risk_offset of −0.5 would give ~80% risk accuracy on these 80 prompts, which is overfitting; left at −0.3.

Kev-4B, three ways to read its confidence 9 Nov 2026 · MLX bf16

Why three runs

As shipped, Kev applies T = 2.41 fitted on its own dev set: only 19% of topic answers clear 0.8 (all right), so the router over-provisions. T = 0.46 on the client (cross-validated log-loss fit) fixes the topic confidence, but the router's temperature only rescales choice answers: complexity and risk keep Kev's flat distributions, squeezed toward the middle, and 14 prompts go to a model cheaper than gold. KEV_TEMPERATURE=1.11 (2.41 × 0.46) makes Kev's server sharpen every answer: same topics, risk 61% → 74%, gold routes 61% → 67.5%.

A confidence temperature per provider

The router raises the quality floor when topic confidence is below 0.8, so a model that is right but unsure still over-provisions. providers.<name>.temperature divides the logits by T before the softmax: it never changes which answer wins, only how confident it sounds. T is fitted by minimising log-loss on half the prompts and measured on the other half (20 random 2-fold splits).

Confident answers and gold routes, before → after

A temperature fixes "right but shy" models (Kev, Clef-flash, the Laya fine-tune) and can't help models whose errors are confident (Von) or that are unsure because they're often wrong (VegaML zero-shot). With 80 prompts, treat fitted values as a starting point.

What the benchmark does

80 labelled prompts, four questions

57 core dev tasks, 8 in other languages, 4 longer than 512 tokens, 7 tricky or ambiguous, 4 with private data. Each prompt gets the router's four questions in one request: topic (choice among 10), complexity (score 0–3), risk (score 0–2) and private data (boolean).

From the answers the router computes a quality floor, raises it when topic confidence is below 0.8, and picks the cheapest of five OpenRouter models above the floor: Qwen 3.7 Flash, DeepSeek V4.1 Flash, GPT-5.6 Luna, Claude Sonnet 5, Claude Opus 5.5.

No prompt is sent to a chat model

Only decisions are compared. The gold route is the model the router picks when fed the human labels. Metrics: topic/complexity/risk accuracy, confident share, ECE (distance between stated confidence and accuracy), route = gold, under/over-provisioned prompts, estimated cost, latency.

Code, cases and setup: docs/benchmark.md. Raw data on this page: the bench's own JSON output, one file per run.
